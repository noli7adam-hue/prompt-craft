# Prompt Craft

*[English version](README.en.md)*

Скилл для Claude Code: создание, улучшение, аудит и миграция промптов для современных LLM — Claude Opus 5 / Sonnet 5, GPT-5.6, Gemini 3.x, Perplexity Sonar, Grok, open-weight.

**Версия 2** — третий класс моделей (frontier-агентные: Opus 5 и новее), 17 практик вместо 12, протокол миграции между поколениями и реестр источников. Что и почему менялось — в [CHANGELOG.md](CHANGELOG.md).

Главная идея: универсального «хорошего промпта» больше нет. Практики, которые работали в 2023-м, на reasoning-моделях 2025–2026 бесполезны или вредны. Скилл сначала определяет класс модели и платформу, и только потом собирает промпт — по канонической структуре и с прогоном через чек-лист.

## Зачем это нужно

Обычная просьба «напиши промпт» даёт усреднённый результат: роль, «думай пошагово», пара примеров, «будь полезным». На reasoning-модели такой промпт работает хуже, чем короткая формулировка цели.

В основе скилла несколько принципов:

- **Класс модели важнее вендора.** Обычная модель — «младший коллега»: точные шаги и примеры. Reasoning — «старший коллега»: цель и критерий готовности. Frontier-агентная (Opus 5 и новее) — промпт настраивается **вычитанием**: модель верифицирует себя сама, и старая обвязка «дважды проверь» теперь работает против качества.
- **CoT перестал быть бесплатным.** Wharton GenAI Lab (arXiv 2506.07142) измерил: на reasoning-моделях «думай пошагово» даёт +2.9…+3.1% точности при росте задержки на 20–80%, а на Gemini Flash 2.5 — минус 3.3%.
- **Внимание модели U-образно.** Начало и конец контекста читаются лучше середины («Lost in the Middle», TACL 2024) — размещение данных и вопроса это учитывает.
- **«Помещается в окно» ≠ «модель это использует».** Сфокусированный контекст стабильно бьёт свалку (Chroma Context Rot).
- **Промпт не готов без проверки.** Минимум — прогон на 3–5 реальных входах, включая краевые, с изменением по одному элементу за раз.
- **Смена модели — это протокол, а не переписывание.** Сначала меняют только модель, потом калибруют глубину, потом снимают лишнее, потом чинят платформенные несовместимости. «После апгрейда стало хуже» почти всегда означает, что всё переехало одним куском.
- **Цифры имеют источник и срок годности.** Волатильные факты (версии, дефолты, лимиты) собраны в отдельный реестр со статусом проверки, а не переписываются по памяти.

## Что внутри

`SKILL.md` — ядро: развилка по классу модели (обычная / reasoning / frontier-агентная), каноническая структура промпта, семнадцать практик, чек-лист качества, список антипаттернов, полный пример цикла.

Справочники подгружаются по необходимости, чтобы не забивать контекст заранее:

| Файл | Когда нужен |
|---|---|
| `references/template.md` | Готовые скелеты: канонический, минимальный, reasoning, Gemini, контракт под frontier, кэш-дружелюбный |
| `references/patterns.md` | Типовая задача: классификация, извлечение, генерация, агент, RAG, judge, structured output |
| `references/models.md` | Целевая модель не Claude: GPT-5.6, Gemini 3.x, Perplexity Sonar, Grok, Mistral, open-weight |
| `references/claude-opus-5.md` | Целевая модель — Opus 5 / Sonnet 5 и новее; миграция на новое поколение; жалобы на многословность, scope creep, лишние перепроверки |
| `references/audit.md` | Разбор и улучшение существующего промпта; протоколы миграции по вендорам |
| `references/security.md` | Промпт обрабатывает недоверенный контент, защита от инъекций |
| `references/context-engineering.md` | Продакшн, агенты, длинный контекст, кэширование, compaction |
| `references/evals.md` | Эвалы, сравнение промптов, LLM-as-judge, авто-оптимизация (DSPy, GEPA) |
| `references/sources.md` | Первоисточник утверждения или проверка волатильного факта |

## Чего он не делает

- Это метод, а не гарантия. Скилл убирает типовые ошибки, но не заменяет эвалы на ваших данных.
- Практики привязаны ко времени. Рекомендации отражают документацию вендоров 2025–2026; модели дрейфуют, при смене версии нужен регрессионный прогон.
- Скилл не защитит от косвенных prompt injection полностью — полного решения не существует (позиция OWASP, Microsoft, Google). Он снижает риск, а не обнуляет его.
- Он не пишет за вас критерии успеха. Если непонятно, что считать хорошим ответом, промпт не спасёт.

## Установка

```bash
git clone https://github.com/kravcovtech/prompt-craft.git ~/.claude/skills/prompt-craft
```

Windows (PowerShell):

```powershell
git clone https://github.com/kravcovtech/prompt-craft.git $env:USERPROFILE\.claude\skills\prompt-craft
```

Для одного проекта — клонируйте в `.claude/skills/prompt-craft` внутри репозитория.

Английская версия лежит в `en/` и ставится копированием этой директории — см. [README.en.md](README.en.md).

Перезапустите Claude Code. Скилл подхватится сам, когда речь зайдёт о промптах; можно вызвать и явно — `/prompt-craft`.

## Как использовать

Просто сформулируйте задачу обычными словами:

- «Напиши промпт для классификации тикетов на 4 категории, целевая модель — Claude Sonnet»
- «Вот мой системный промпт, он игнорирует часть инструкций — почини»
- «Сделай промпт для RAG-ответов по документации, устойчивый к инъекциям»
- «Промпт для GPT-5 с reasoning: извлечь сущности из договора»

На выходе — готовый промпт одним кодовым блоком, короткое объяснение принятых решений, при необходимости блок «Параметры API» (reasoning_effort, thinking_level, response_schema) и предложение, как проверить результат.

Скилл работает и без Claude Code: `SKILL.md` можно вставить в любой агент как системную инструкцию.
